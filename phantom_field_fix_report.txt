PLAIN ENGLISH
--------------------------------------------------------------------------------
Your diagnosis was exactly right -- it was one character. When Amazon rejects a
listing, its error messages come as sentences like "The Listing data provided is
different..." or "Your offer to the SKU cannot be added...". The auto-fix editor
tries to pull the FIELD NAME out of each error so it can show you a box to fix.
But the little pattern-matcher that did that pulling was set to ignore
capital-vs-lowercase, so it grabbed the first word of Amazon's plain-English
sentence -- "The", "Your" -- and drew them as if they were real fields you had to
fill in. Real Amazon field names are always lowercase with underscores (like
part_number), never capitalised words.

I removed that one setting so the matcher now only grabs genuine lowercase field
names. And, as you asked, I added a SECOND safety net: before drawing ANY box, the
editor now checks the field name against the actual product schema it already
downloaded. If the name isn't a real field in that schema, it doesn't draw a box
-- it shows Amazon's message as plain text instead, clearly labelled "Amazon
message (not an editable field)." So even if a bad word ever slips past the
pattern again, it can't become a phantom field.

What you'll see change: on the listings that currently show "The"/"Your" as empty
required fields, those phantom boxes disappear. The underlying Amazon message
still shows -- as read-only text, not a field you're expected to fill.
